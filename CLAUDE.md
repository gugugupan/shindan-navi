# トレカカレンダー (shindan-navi.app)

Brand トレカカレンダー (formerly 新弾ナビ; the home page JSON-LD keeps 新弾ナビ as `alternateName`). Feature names: 新弾カレンダー (`/releases/`) and イベントカレンダー (`/events/`). Repo, Worker, D1, Pages project, localStorage keys and the domain keep the `shindan-navi` names.

TCG / トレカ new-release calendar for Japanese players: every title's boosters, decks and sets on one calendar, with favourites (★), add-to-calendar and SEO landing pages. Static site plus a TCG event calendar (`/events/`), both served by one Cloudflare Worker: static assets from `dist/`, `/api/*` from the Worker with D1.

## How it fits together

```
data/items.json ─┐
data/overrides.json ─┼─ scripts/build.py ─→ dist/ (pages, /events/, sitemap, robots, fonts) ─┐
src/template.html, src/events.html ─┘                                                    ├─ Worker "shindan-navi" (wrangler.jsonc)
public/ (thumbs, og, icons, _headers) ──┘                api/src/ (/api/v1/*) ─ D1 ────┘   on shindan-navi.app
                          ↑ push to main runs .github/workflows/deploy.yml (build + wrangler deploy)

scripts/refresh.py (local, by hand, reviewed): tools/release-collectors/{cardlabo,torecamap,official} → data/releases/ (git-ignored)
    → scripts/update_data.py (merge) → data/items.json, items-archive.json, meta.json, update-report.md, public/thumbs → build → verify → packet
tools/event-collectors/ (local)  → data/events/ (git-ignored) ─ api/scripts/import-events.mjs --target remote (manual) → D1
```

- **Publishing = pushing to `main`.** The workflow builds and deploys code + `dist/`; it never edits data and never touches D1. Until the cutover (repo variable `LIVE_HOST` unset/`pages`) the live site is still the Pages project, built without `/events/`; the Worker only gets a preview deploy. `LIVE_HOST=worker` switches deploys to the Worker with the custom domain. Details and rollback: README.md › Deploy. `scripts/deploy.sh pages|worker [--domain]` is the manual fallback.
- **One Worker, one config.** `wrangler.jsonc` at the repo root (assets `dist/`, `run_worker_first: ["/api/*"]`, D1 binding `DB`, no routes). Its `database_id` is a placeholder: `api/scripts/remote-config.mjs [--domain]` writes the git-ignored `wrangler.remote.json` with the id from `D1_DATABASE_ID` (GitHub secret in CI, env var locally) and, with `--domain`, the `shindan-navi.app` custom domain. Never commit the real id.
- **Event data is never committed** (owner decision; `/data/events` is git-ignored). Collectors write it locally; it reaches D1 only by a manual import (`cd api && D1_DATABASE_ID=… npm run import:remote -- --plan`, read the per-game review summary, then `-- --yes`). The importer's guards replace git review: schema checks, complete runs (or `--allow-incomplete GAME`), no >20% shrink against D1 (or `--allow-shrink`), `--max-writes`. It diffs against D1 and writes only changes. D1 stays on the Free plan: see `api/README.md` › D1 budget before changing queries, indexes or the importer.
- **Migrations are applied by hand.** CI deploys code but never migrates D1: apply a new `api/migrations/*.sql` remotely (`npm run import:remote -- --yes` runs `migrations apply` first, or `wrangler d1 migrations apply shindan-navi-events --remote --config ../wrangler.remote.json`) before pushing code that needs it.
- **/events/ day view has a Google map** (owner decision: Google Maps). Built only with `MAPS_BROWSER_KEY` (repo variable → Worker build; referrer-restricted browser key); without it, or when Google fails, a placeholder and the list keep working. The Maps script loads only when a day's map opens. Classic `google.maps.Marker` (no Map ID). Details and the key checklist: README.md › Event map.
- **Google login is dark until enabled.** The page UI (user control, sync wording, LOGIN parts of `/privacy/`) is built only with `LOGIN_ENABLED=1` (repo variable → Worker build; always off with `BUILD_EVENTS=0`), and build.py refuses it while `src/privacy.html` has owner placeholders. The API side answers 404 until its secrets are set: `contracts/README.md` › Accounts API. Logged-out visitors make no `/api` calls on `/releases/`: the page calls `/api/v1/me` only while the `__Host-sn_user` cookie is set.
- **Feedback form is dark until enabled.** `/feedback/` (form → `POST /api/v1/feedback` → D1 `feedback` + a mail via an Email Routing `send_email` binding, Cloudflare Turnstile against spam) and all links to it are built only with `FEEDBACK_ENABLED=1` (repo variable, Worker build only) plus `TURNSTILE_SITE_KEY` and `PRIVACY_EFFECTIVE_FEEDBACK` in build.py. The Worker answers 404 until `TURNSTILE_SECRET_KEY` / `FEEDBACK_TO` are set and `remote-config.mjs` adds the binding (only with `FEEDBACK_ENABLED=1`). The recipient lives only in the `FEEDBACK_TO` secret, never in git. noindex, not in the sitemap; rows kept 1 year. Setup and details: `api/README.md` › Feedback.

## Data model

- `items.json`: `{id, date, game, name, pack, box, url, thumb, approx, sources, source, changed}`. `changed` = the merge run's TODAY when the item was added or a shown field changed (rule: `contracts/releases.md` › `changed`). `id` = `i` + sha1(`game|normalised name`)[:10] — stable across date changes; never renumber.
- `items-archive.json`: released items that aged out of `items.json` (slim `{id, date, game, name, pack, box, per_box, per_pack, url, thumb, approx, source, changed}`), written by the merge, kept ~2 years. Only their `/item/<id>/` pages use it (発売済み, no 新弾カレンダーで見る, in the sitemap with `changed`); never the calendars, title / month pages or `/`.
- `source` = where the release lives on its original site: `{url, key, site}`. `url` is the canonical official page (redirects resolved), `key` the official product code (OP-18, UA57BT, VG-DZ-BT17 … via `scripts/sourcekey.py`) or else the normalised name, `site` is `official` or `aggregator` (only seen on カードラボ / トレカの地図). **De-duplication goes by source first** — same product code within a title, or same page + key — and only falls back to name similarity / Jev when that fails. When the official pilot matches an item it can adopt the official source (`--adopt-sources`), so the next run pairs it by identity.
- `overrides.json`: hand fixes by id — `url`, `thumb` (`""` pins the placeholder), `name`, `date`, `pack` / `box` (`""` = no price), `approx`, `hide: true`. `_name` / `note` are labels for people. Applied by both the updater and the build; never overwritten.
- `approx: true` = stand-in image (key visual, other edition). Shown with 参考画像; the updater swaps in a real source image when one appears.
- Favourites are keyed by item id in the viewer's localStorage (`tcg.stars`); legacy `date|name` keys are migrated on load. Logged in, `src/corner.html` syncs `tcg.stars`, `tcg.ev.filters` and `tcg.calAskOff` with the account (localStorage stays the cache the pages read; `tcg.sync.base` = last server state, local changes are pushed as a diff; another account's login replaces local data; logout and account deletion keep local copies).
- Calendar pages describe release lists with ItemList JSON-LD, including entries without images or prices. They are aggregations, not single-product or merchant pages: do not add Product/Offer markup, infer stock from release dates, or invent reviews, ratings, shipping or return policies to satisfy shopping-result warnings.

## Decisions the owner made (keep them)

- Top of every page is only the logo row (logo lockup, the tool tabs after it, the corner on the right) and the toolbar. The 次の発売日 card next to the logo was removed by owner decision (2026-11-19); don't bring it back. Page H1, breadcrumbs and lead text (with 次の発売は…) sit **below** the calendar as muted secondary text. Exception (owner decision 2026-11-20): `/voices/` puts its h1, intro line and symbol legend above the calendar. The `/voices/<date>/` archive pages have no calendar: crumbs, h1 and lead sit at the top.
- No search box. Default title chips: MTG, ヴァイスシュヴァルツ, ポケモンカード, UNION ARENA, ONE PIECE; the rest behind ほか○タイトル.
- Desktop calendar shows at most 3 items per day; quiet weekdays become slim columns; today is gold. Mobile: day list collapses to starred items + the first item, with 閉じる under the date as well as at the bottom.
- Star button is the full-height right strip of each card (34px desktop, 46px mobile).
- The product switch (新弾カレンダー ⇄ イベントカレンダー ⇄ 話題カレンダー tabs; with three, 761-900px shows the short names 新弾 / イベント / 話題) sits right after the logo on desktop/tablet and is a bottom tab bar on phones ≤760px (owner decision 2026-11-19). The top-right corner of the logo row is one control group on every page, left to right: settings (gear menu with テーマ 自動 / ライト / ダーク, default follows the system; later settings go here), and with login enabled the user control (ログイン, icon-only on phones; logged in: avatar menu 設定 / ご意見・ご要望 (when feedback is enabled) / ログアウト; account deletion only inside the 設定 sheet, owner decision 2026-11-20). The toolbar holds only calendar controls. `/events/` mirrors the release calendar (owner decision 2026-11-19): same toolbar (month nav + 今日 + カレンダー / リスト, title chips with この月 N 件, then a 都道府県 / イベント形式 / 曜日 row; chips and filters behind 絞り込み on phones, the N 件 count repeated under the toolbar there) and per-title data freshness in the muted text below the calendar. Footer nav: a ツール row and プライバシーポリシー on every page (also on 404), plus ご意見・ご要望 when the feedback form is enabled (also in the gear menu and the avatar menu, with `?from=<path>`). New tools are added to `TOOLS` in build.py.
- Game icons (owner decision 2026-11-20): every game chip / label on every page has a small decorative icon before the name (`aria-hidden`, fixed 14-16px), from one map `GAME_ICON` in build.py by display name, rendered by `gi()` (slot `/*GICON*/`). ONE PIECE, UNION ARENA, DBFW, デジモン, ヴァイス, ヴァンガード, ホロライブ, ラブライブ！OCG and MTG (9 titles) use their official site favicon (32px PNGs in `public/gi/`, self-hosted, never hotlinked, on a white tile for dark mode; for identification only); ポケモンカード (`ptcg.svg`, a red / white ball) and 名探偵コナン (`conan.svg`, a black D with a white bust) use small flat SVGs we drew ourselves (no official asset, same white tile); `gi()` takes `.png` and `.svg` alike. All other titles get our own monogram tile in the game colour (unknown titles: first character). 遊戯王 never uses a KONAMI asset. Calendar day dots (/events/ cells, /voices/ phone dots and their colour key, the /events/ map pin key) stay dots.
- Event rows (owner decision 2026-11-20): `/events/` day lists and the home page's game columns share one renderer, `src/evrow.html` (`window.snEv`, EVROW slot): name → time ・ venue (+ city) → registration facts / source link. Display names drop month markers (（11月開催）, 【26/11】, 【2026年11月】 …; data and API untouched), and a row does not repeat the game it sits under. Events of a day with the same games, type and display name fold into one expandable row (「スタンダードバトル — 20店舗」, start-time range); counts cover the loaded rows only (以上 while the day has more) and no request is added. Metadata on /, /events/ and /releases/ is at least 12px, event / product names 14-16px.
- Starring an upcoming item asks to add it to Google Calendar / .ics (前日20時 alarm) unless 今後は確認しない was ticked.
- Thumbnails and data sources stay as they are and are **not credited** on the page (owner's choice, risk acknowledged).
- Keep this site standalone: don't cross-link it from or to other sites without asking the owner.
- Only the 10 main titles get landing pages for now. Weekly auto-refresh of data is deliberately not automated (`scripts/refresh.py` is run by hand).
- Official sources win: when the official site lists variants separately (e.g. four commander decks) the calendar should list them separately too, each with its own source.

## Event game palette

Each `/events/` game has a fixed colour pair (`c` light, `cd` dark) in `GAMES` (`src/events.html`) and `EV_GAMES`
(`src/home.html`); the pages set them inline as `--gl` / `--gd` and `src/template.html` turns them into `--g` (marks),
`--gt` (text) and `--gtint` (pressed chips, chips on /) per theme. Map pins always use the light colour (the basemap is
light). Release titles keep their computed hue (`--h`). Colour is never the only cue: chips, columns, tags and the map
legend carry the name, calendar-cell dots a tooltip.

Picked greedily (2026-11-19) to keep the four original colours and maximise the worst pair over all colours, in both
themes, under normal vision and simulated protan/deutan (OKLab ΔE×100; dataviz `validate_palette.js`). Every colour has
≥3:1 contrast on white (light) and on `#181b27` (dark), except PTCG's original gold (2.7:1 on white). Take new games' colours from the next free slot in order:

## Gotchas

- Right after a deploy, brand-new asset URLs can answer 404 / HTML for a few seconds; wait ~15 s before checking live. `public/_headers` deliberately sets no long-lived cache rules; it applies to static assets only, not to Worker (`/api/*`) responses.
- Workers static assets: `/pokemon` → 307 `/pokemon/`, `/x/index.html` → `/x/`, unknown paths → `404.html` with status 404. `*.workers.dev` (version preview URLs) answer with `X-Robots-Tag: noindex`. `public/_headers` restores the `X-Content-Type-Options` / `Referrer-Policy` headers Pages used to add.
- `/api/v1/events*` responses are cached per colo for 24 h under the data version (bumped by each import; isolates re-read it within 60 s), browsers 5 min. The API accepts exactly what the page sends (pref/from/until/game/type/days, limit 50, cursor) with month-shaped ranges; anything else is 400. `/events/days` reads the precomputed `day_counts`, filtered `/events` pages jump to matching days via `day_counts` and scan at most 200 rows per location. Misses are rate-limited per client (`API_LIMIT`, IPv6 by /64) and per location (`API_BREAKER`). If D1 fails, cached answers keep serving (last known version). Adding an API parameter or a page request pattern changes the read budget: update `api/README.md` › D1 budget. Cloudflare documents working Cache API operations only for custom domains, so on `*.workers.dev` preview URLs assume every request reads D1.
- カードラボ (`/special/2028/`, parser `tools/release-collectors/cardlabo/parse.py`) has no years in its headings — the collector picks the year whose weekday matches TODAY. トレカの地図 (`tools/release-collectors/torecamap/parse.py`) takes `?year=YYYY&month=M`; its HTML also carries an RSC copy of every item — only items with a rendered `ProductInfo_name` are real. Title labels map to display names via `GAME` in `tools/release-collectors/lib/common.py`.
- A refresh without `TYPESAFE_API_KEY` / `OPENROUTER_API_KEY` (or with `--no-official`, or stale/missing official files) skips the official collector and enrich. The merge then keeps what the last official run gave each item (`official` in `sources`; `source`, `url`, box info are kept anyway): not checked is not gone. The same holds per title for a partial official run (`collect.py --games`, or a title whose page failed; scope in `_run.json` `games`). No new official items, official prices or dates come in such a run. An official name (`name == official_name`) is kept in every run. The packet WARNING about lost `official` only fires for titles the official step checked. A new worktree has no `.env`: copy it in to run the official step, never commit it.
- Some official sites (Bandai: onepiece-cardgame.com, unionarena-tcg.com, gundam-gcg.com, dbs-cardgame.com, fanstars-league.com) serve incomplete TLS chains. Browsers complete them via AIA, OpenSSL in a uv/python.org Python does not ("unable to get local issuer certificate"). `lib/common.py` injects `truststore` (OS verifier) for every fetch; never disable verification instead.
- `source.url` is an identity key, not an address: `canonical_url` drops `www.`, and yugioh-card.com / konami.com only answer on `www.` (Hostname mismatch otherwise). Box-info enrich (`fill_box_info`) falls back to the source URL and retries a Hostname mismatch on the `www.` host.
- yu-gi-oh.jp blocks curl for HTML (Cloudflare) but its image URLs download fine — open articles in the browser pane, copy the image URL, fetch with curl.
- Official "NOW DESIGNING / NOW PRINTING" images are placeholders — never use them as thumbnails; pin `thumb: ""` instead.
- Fonts are subset at build time from the characters on the built pages (plus kana/ASCII). Sources are OFL fonts in `brand/fonts/`.
- The logo lockup (`brand/torecal-lockup-*.svg`, concept 金の日: calendar with a gold card) has the wordmark outlined from M PLUS Rounded 1c ExtraBold (OFL; the font is not in `brand/fonts/` because no page uses it as text). `src/template.html` inlines the light lockup with CSS variables instead of its fixed colours, so it follows the theme; the other pages take it from there. The favicon (`brand/icon/favicon.svg`) and app icon (`brand/icon/app-icon.svg`) are simplified marks; don't use the full lockup at icon sizes.
- The repo is public: never commit `.wrangler/`, `wrangler.remote.json`, the D1 database id, tokens, account ids or personal emails.

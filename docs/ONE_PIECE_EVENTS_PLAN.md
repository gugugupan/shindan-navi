# ONE PIECE 赛事查询：实施计划

## 目标与第一版范围

在新弾ナビ内增加未来赛事入口，首先支持日本语版 ONE PIECE 卡牌游戏。按日本全国的都道府县、日期与赛事类型筛选，不预设用户只关注东京。覆盖范围最终取决于来源可取得的数据；页面必须显示最后更新时间和覆盖范围。

主要流程：选择地区 → 选择日期/本周末 → 查看赛事 → 前往 TCG+ 查看详情和报名。

赛事列表以日期排序；卡片展示名称、赛事类型、开始时间、门店、地区、费用和报名方式。未知字段显示未确认，费用未知不能显示免费。报名状态与取消状态分开保存；未来举办不等于开放报名。

## 里程碑 1：验证真实来源

1. 使用可运行 JavaScript 的浏览器检查 TCG+ 的正常赛事查询流程，选择 ONE PIECE 日本语版与日本地区。
2. 核实公开可访问的请求、分页、可用字段、ID 和详情链接；如需登录，通过正常登录流程检查可见范围。
3. 读取至少两个都道府县、多个日期的真实赛事样本，核对地点、时区、报名截止时间、先着/抽选与取消状态。
4. 形成字段映射和覆盖报告；如果自动获取不可行，明确记录原因并评估可审阅的手工导入。

验收：有可追溯的真实样本和可重复的数据获取路径。无法通过此验收时，不进入假定可以持续采集的实现。

## 里程碑 2：后端与导入

沿用现有 Cloudflare 托管，候选架构为独立 Worker API + D1，现有 Python 商品页继续构建。先提供本地数据库与本地预览，不先创建生产资源。

- `venues`：来源门店ID、名称、国家、都道府县、城市、地址；经纬度仅在来源提供时保存。
- `events`：内部ID、游戏与语言版本、来源赛事ID、venue关联、名称、类型、开始/结束时间、时区、报名起止时间、费用与币种、人数上限、报名方式、报名状态、取消状态、来源URL、最后观察时间。
- `imports`：查询范围、开始/结束时间、成功/失败与数量，用于说明数据覆盖和排查失败。
- 上述字段是候选模型，不代表 TCG+ 已提供。来源缺失字段允许空值，容量不等于实时余位。
- 来源ID确定后据此幂等更新；改期保持内部ID；来源暂时缺失不自动标成取消。
- 公共 API 按游戏、地区、时间范围和游标分页查询，限制请求范围与返回量。
- 导入为受保护的管理操作；第一版保持手动触发，定时更新另行确认。

验收：重复导入不重复，改期/取消/抓取失败行为正确，按地区和日期筛选准确；原有商品ID与人工修正保留。

## 里程碑 3：赛事页面

新增 `/events/`，以 ONE PIECE 为首个游戏，提供都道府县、日期、本周末、赛事类型筛选与分页。沿用站点日语界面和现有品牌，手机列表优先。

每条赛事跳转至已核实的 TCG+ 详情/报名入口；个人报名和当选状态由 TCG+ 提供。页面展示数据更新时间，获取失败时明确显示旧数据状态。用真实导入数据验证筛选、空结果、移动端、报名未知与取消状态。

验收：本地可预览完整查询流程，有真实赛事可逐条比对；发布前单独审阅。
